# Агент в чате Webim

Чат на store.softline.ru работает на Webim (в коде страницы аккаунт `storesoftlineru.webim.ru`). Адаптер `app/webim.py` подключает агента в этот чат как бота через External Bot API 2.0 ("Умный бот"): клиент пишет в привычном окне чата сайта, агент отвечает там же, передача менеджеру переводит чат оператору в панель Webim, а при сбое агента чат уходит в общую очередь операторов.

Документация Webim, по которой сделан адаптер: [Умный Бот 2.0](https://webim.ru/kb/bots/smart-bot/v-2-0.html), [Добавление бота](https://webim.ru/kb/bots/add-new-bot.html), [Типы сообщений](https://webim.ru/kb/dev/basic-objects/message-types.html). Ниже ссылки на разделы первой страницы даны якорями, например `#bot-errors`.

## Как это работает

1. Webim шлет событие на адрес бота `https://<адрес стенда>/api/webim/<WEBIM_SECRET>`. Адаптер сразу отвечает `{"result": "ok"}`: API асинхронный, Webim ждет только подтверждения приема, а другой ответ считает отказом и переводит чат в общую очередь (`#description`, `#bot-errors`).
2. Ход агента идет в фоне тем же кодом, что у чата сайта: та же очередь к модели (`MAX_PARALLEL_TURNS`), тот же срок хода (`TURN_DEADLINE`), те же проверки цен и скидок, тот же журнал и экран оператора. Диалог агента на каждый чат Webim свой: `webim-<номер чата>-<подпись>`.
3. Ответ уходит вызовами API Webim с заголовком `Authorization: Token <WEBIM_TOKEN>` (`#auth`).

| Событие Webim | Что делает адаптер | Вызов Webim |
|---|---|---|
| `new_chat`, в нем сообщения, накопленные до назначения боту (`#assigning-to-bot`) | один ход агента на все эти сообщения | как ниже |
| `new_message`, текст посетителя (`#new-message`, `#bot-text`) | ход агента | `send_message` с `kind: operator`: ответ простым текстом, под ним карточки товаров строками (название, цена из каталога, артикул, ссылка на страницу магазина) (`#text-message`) |
| в ответе есть варианты выбора | кнопки: варианты и "Позвать менеджера" | `send_message` с `kind: keyboard` (`#button-message`) |
| агент сформировал черновик КП | файл по ссылке `PUBLIC_URL/quotes/<номер>.pdf?k=<подпись>`: Webim сам скачивает файл (`#file-message`) | `send_message` с `kind: file_operator`; Webim не принял файл, тогда ссылка текстом |
| агент передал обращение менеджеру | перевод в отдел продаж | `redirect_chat` с `dep_key` (`#redirect-to-department`); отдел не принял чат или `WEBIM_DEP_KEY` пуст: общая очередь (`#redirect-to-queue`) |
| модель не ответила, срок хода вышел, сбой кода, Webim не принял ответ | ответ о передаче менеджеру | `redirect_chat` в общую очередь |
| нажата кнопка варианта (`#bot-buttons`) | текст кнопки идет в ход как реплика клиента, как в чате сайта | как у текста |
| нажата кнопка "Позвать менеджера" | обращение заводит тот же код, что у кнопки в чате сайта, модель не вызывается | `send_message`, затем `redirect_chat` в отдел |
| файл посетителя, `state: ready` (`#bot-file`) | просьба написать вопрос текстом, один раз на файл | `send_message` |
| прочие события и `message_updated` без готового файла (`#message-update`) | ничего | нет |

Повтор доставки. При сбое связи или таймауте Webim повторяет событие до пяти раз с паузами 2, 4, 8 и 16 секунд (`#bot-errors`). Адаптер помнит номера принятых сообщений (поле `id` сообщения, у события целиком номера нет) один час: повтор подтверждается, но второго хода и второго ответа нет.

Защита адреса. Запросы Webim к боту не авторизуются, документация предлагает дописать секрет в конец адреса бота (`#outcoming-requests`): это `WEBIM_SECRET`. Запрос с другим окончанием адреса получает 403. Номер чата Webim идет подряд, поэтому диалог агента назван с подписью ключом бота: по номеру чата диалог не открыть через чат сайта и не подставить в память о прошлом визите.

## Подключение в кабинете Webim

По разделу `#setup` и странице "Добавление бота":

1. Создайте оператора для бота. Webim советует отдельного оператора на каждого бота и не больше одного бота в отделе.
2. "Настройки", раздел "Боты", кнопка "Создать новый бот".
3. "Оператор для бота": оператор из п. 1. "Тип бота": "Умный бот", версия `2`.
4. "Ссылка на внешний API": `https://<адрес стенда>/api/webim/<секрет>`, где секрет это длинная случайная строка, та же, что в `WEBIM_SECRET`.
5. "Статус": "Онлайн" (бот получает новые чаты, кнопка на сайте показывает "Онлайн"). "Порядок сортировки": меньше число, раньше этот бот получает чат.
6. Сохраните. Webim сгенерирует токен бота и покажет его в поле токена: это `WEBIM_TOKEN`.
7. Ключ отдела, куда агент переводит чат при передаче менеджеру (например, отдел продаж): `WEBIM_DEP_KEY`.
8. Чтобы черновик КП приходил файлом, в настройках аккаунта Webim в разрешенных для бота типах файлов должен быть PDF: `robot_allowed_upload_file_types` (расширение `pdf`) и `robot_allowed_upload_file_content_types` (`application/pdf`) (`#file-message`). Без этого клиент получит ссылку на КП текстом.

## Настройки на нашей стороне

В `.env` (описание и в `.env.example`), затем перезапуск сервиса:

```
WEBIM_TOKEN=<токен бота из кабинета>
WEBIM_SECRET=<тот же секрет, что в конце ссылки на внешний API>
WEBIM_API_URL=https://storesoftlineru.webim.ru
WEBIM_DEP_KEY=<ключ отдела продаж; пусто = общая очередь>
PUBLIC_URL=https://<адрес стенда>
```

Без `WEBIM_TOKEN` адаптер не подключается и адреса `/api/webim/...` нет. Лимит сообщений в минуту с одного адреса (`CHAT_RATE_PER_MIN`) к событиям Webim не применяется: все они приходят с адресов Webim. Суточный потолок расхода на модель (`DAILY_BUDGET_RUB`) действует, как в чате сайта. Адрес стенда должен открываться из интернета по HTTPS: на него Webim шлет события и с него скачивает PDF. Диалоги из Webim видны на экране оператора, как диалоги чата сайта; обращения менеджеру также приходят в Telegram, если он настроен.

## Что проверено без живого Webim

Поддельный Webim (`eval/webim_emulator.py`, класс `FakeWebim`) это HTTP-сервер с адресами `/api/bot/v2/send_message`, `redirect_chat`, `close_chat`. Он проверяет заголовок `Authorization: Token ...` и форму вызова по документации (обязательные поля, `kind`, id кнопок не длиннее 24 знаков из латиницы, цифр, `-` и `_`, нельзя одновременно `operator_id` и `dep_key`) и отвечает ошибкой, как Webim, если вызов неверный.

Тесты `tests/test_r3_webim.py` (модель-сценарий вместо модели, синтетический каталог):

- вопрос о цене Kaspersky на 10 ПК: ответ с ценой из каталога, карточка строкой, кнопки вариантов и "Позвать менеджера";
- просьба о скидке 15%: передача менеджеру и `redirect_chat` с `dep_key`; без `WEBIM_DEP_KEY` общая очередь; отдел ответил `target-is-offline`: общая очередь;
- сбой модели и сбой кода хода: ответ о передаче и `redirect_chat` в общую очередь; Webim не принял ответ: общая очередь;
- повтор доставки `new_chat` и `new_message`: один ход и один ответ;
- черновик КП: `file_operator` с полной подписанной ссылкой, по ней отдается PDF без ключа оператора; PDF не разрешен в аккаунте: ссылка текстом;
- кнопка "Позвать менеджера": обращение без вызова модели и перевод в отдел; кнопка варианта: ее текст идет в ход;
- подтверждение приема приходит сразу, пока ход еще идет;
- файл посетителя: один ответ на готовый файл, на ход загрузки ответа нет;
- неверный или незаданный секрет: 403; битое событие: 400; незнакомое событие: подтверждение без действий;
- диалог Webim не открывается через чат сайта по номеру чата;
- сервер подключает адаптер только с `WEBIM_TOKEN`.

Эмулятор против запущенного экземпляра проигрывает шесть шагов и печатает каждый вызов бота:

```
WEBIM_TOKEN=demo WEBIM_SECRET=s3cret WEBIM_API_URL=http://127.0.0.1:8099 WEBIM_DEP_KEY=sales \
    uvicorn app.web.server:app --port 8053
python -m eval.webim_emulator --base http://127.0.0.1:8053 --token demo --secret s3cret --port 8099
```

Пример вывода (сокращен) на экземпляре, где на запросы к модели через мост (`LLM_PROVIDER=bridge`) отвечал сценарный исполнитель:

```
[1] new_chat, чат 57170110, новый чат: Сколько стоит Kaspersky Endpoint Security на 10 ПК?
    бот подтвердил прием: 200 {"result":"ok"} за 50 мс
    -> ответ агента: Kaspersky Endpoint Security для бизнеса Расширенный ...: 1 444,50 руб. за лицензию. ...
    -> кнопки: Оформить КП | Другой срок | Позвать менеджера
[2] new_chat, чат 57170110, повтор доставки того же события: ...
    -> вызовов нет: второй ход не запускался
[3] new_message, чат 57170110, новое сообщение: Сделайте скидку 15%, тогда возьмем
    -> ответ агента: Сам я могу дать скидку до 5%, больше согласует менеджер: ...
    -> redirect_chat: в отдел sales
[4] new_chat, чат 57170111, новый чат: Подготовьте КП на Kaspersky Endpoint Security Стандартный на 10 ПК ...
    -> файл КП-20261126-0126.pdf (application/pdf), скачан: 200 application/pdf, 125 КБ
[6] new_message, чат 57170112, кнопка: нажата кнопка Позвать менеджера
    -> redirect_chat: в отдел sales
```

С настоящей моделью команда та же: тексты ответов будут ее, а шаги проверяются по виду вызовов (ответ, перевод, файл). Код выхода 1, если какой-то шаг кончился не так. Диалоги эмулятора остаются на экране оператора экземпляра.

## Что не проверено на живом аккаунте Webim

Все ниже сделано по документации и не проверялось на настоящем Webim, доступа к аккаунту нет.

- Формат событий взят из документации. Полного примера нажатия кнопки в ней нет, поле `data.button` описано словами.
- Срок ответа бота на событие в документации 2.0 не назван (у версии 1.0 это 5 секунд по умолчанию). Адаптер подтверждает прием за десятки миллисекунд, поэтому срок не должен быть важен.
- Каким событием приходит готовый файл посетителя, `new_message` или `message_updated`, документация не уточняет: адаптер отвечает на готовый файл в обоих.
- Тело успешного ответа `send_message` и `redirect_chat` не описано: успехом считается код 200 без поля `error`.
- Как окно Webim показывает ссылки и переносы строк в тексте бота, не проверено: адаптер шлет простой текст без разметки.
- Кнопки в Telegram выглядят как обычная клавиатура, во ВКонтакте и WhatsApp как нумерованный список, где кнопка засчитывается по ее номеру (`#bot-buttons`). Проверено только для формы вызова.
- Перевод, когда все операторы отдела офлайн: адаптер не ставит `allow_redirect_to_offline_dep` и при отказе отдела переводит в общую очередь. Если и она не приняла чат, чат остается у бота, а обращение остается на экране оператора и в Telegram.
- Скачает ли Webim PDF с адреса стенда и разрешен ли PDF в настройках аккаунта заказчика.
- Чат вернули боту после оператора: по документации придет `new_chat`, агент продолжит тот же диалог.
- Номера принятых сообщений хранятся в памяти процесса: перезапуск сервиса в те 30 секунд, когда Webim повторяет доставку, может дать второй ответ.
- Секрет адреса бота виден в журнале запросов сервиса (строка с адресом), как и в настройке бота в кабинете Webim.
