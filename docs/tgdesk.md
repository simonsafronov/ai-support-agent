# Telegram Mini App: одно обращение менеджера

**Контракт кнопки для `notify.py`:** `InlineKeyboardButton.web_app.url = PUBLIC_URL.rstrip('/') + '/tgdesk?handoff=' + str(handoff_id)`. Это положительный номер строки `handoffs`, не `session_id`, не chat ID и не право доступа. Например: `{"text":"Открыть обращение","web_app":{"url":"https://desk.example.invalid/tgdesk?handoff=42"}}`. Кнопка типа `web_app` предназначена для личного чата пользователя с ботом. Не подставлять её в группу или канал, не заменять на `url`: обычная ссылка не даёт подписанного запуска. `PUBLIC_URL` для Telegram должен быть HTTPS. Работы по отправке кнопки не входят в этот модуль.

## Кто может открыть

- На сервере нужны `TG_TOKEN` того же бота и отдельный `TG_MANAGER_IDS` — десятичные положительные Telegram **user ID** через запятую (пробелы вокруг элементов допустимы). Без списка или при любом некорректном элементе, в том числе `*`, не проходит никто. Нет наследования прав от `TG_CHAT`, `ADMIN_TOKEN` или `username`. Каждый включённый менеджер может открыть любое рабочее обращение по номеру; это не модель персонального назначения заявок.
- `GET /tgdesk?handoff=N` возвращает только пустой HTML. Приложение берёт исходную строку `initData` из Web App / параметра запуска `tgWebAppData` во фрагменте WebView и убирает фрагмент из адресной строки. Нет внешнего SDK, cookie с правами, сохранения строки в browser storage или добавления её в ссылки. Обновление страницы без данных запуска требует заново нажать кнопку в Telegram.
- Каждый запрос данных, PDF или ответа передаёт `Authorization: tma <initData>`. Сервер использует [протокол Telegram для bot token](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app): разбирает query-string один раз, отвергает дубликаты, исключает только `hash`, сортирует остальные поля, соединяет `k=v` символом LF. Первый HMAC-SHA256: ключ `WebAppData`, сообщение — токен бота. Второй HMAC-SHA256: ключ — бинарный результат первого, сообщение — строка проверки. Сравнивается hex-значение в постоянное время. Дополнительные поля, в том числе `signature`, если оно пришло, участвуют в HMAC.
- Возраст подписанного `auth_date` — от 0 до **300 секунд** включительно. Нужны синхронизированные серверные часы; будущая, устаревшая или повреждённая подпись даёт `401`, верная подпись постороннего аккаунта — `403`. После проверки подписи сверяется точное целое `user.id`. `initDataUnsafe` не используется. Подпись является краткоживущим предъявительским удостоверением: не записывать `Authorization` в журналы прокси и не пересылать его.

## Данные и действия

Все методы ниже требуют той же проверки на каждый вызов и возвращают `Cache-Control: private, no-store`. Они не вызывают административные HTTP-методы и не выдают ключ оператора.

| Метод | Путь после `/api/tgdesk/handoffs/{id}` | Что делает |
|---|---|---|
| GET | (пусто) | Карточка, контакт, запрос клиента, история этого диалога (в пределах последних 200 записей), список документов |
| GET | `/documents/{quote\|invoice}/{doc_id}` | PDF только из диалога выбранного обращения. Для демо-счёта нужен статус `issued`; черновик не скачивается. Нет публичной ссылки с подписью |
| POST | `/answer` | Единственное поле `{"answer":"текст"}`, 1–4000 символов, не только пробелы. `200 {"ok":true}` при успехе |

Сервер сам находит `session_id` по `handoff_id`. «Запрос клиента» — последняя реплика пользователя в этом диалоге до открытия выбранного обращения, но не до предыдущего обращения того же диалога. Более поздние сообщения не подменяют исходный запрос; они остаются в истории. Контакт, история и документы в публичную оболочку не встраиваются.

Ответ идёт в `manager_answer(handoff_id, answer)` без обучения базы знаний. Покупатель видит его через штатный `/api/session/{session_id}/answers`; вручную выбирать получателя нельзя. У закрытого или возвращённого обращения форма недоступна; устаревшая открытая вкладка получает `409`. Диалоги `demo`/`eval-…` исключены. У Webim после передачи отвечает оператор в Webim: его карточка доступна только для чтения, поскольку стандартный `manager_answer` записывает в чат сайта, а не отправляет в транспорт Webim.

## Проверить локально без отправки

Из корня **чистой копии без `.env`**, с Python проекта, pytest и локальными зависимостями. Не использовать `data/db`, даже для чтения; не запускать штатный lifespan с фоновыми потоками.

```sh
D=$(mktemp -d)
env -i PATH=/usr/bin:/bin HOME="$D" APP_DB="$D/app" CATALOG_DB="$D/catalog" \
  KB_DB="$D/kb" CARDS_DB="$D/cards" QUOTES_DIR="$D/quotes" BRIDGE_DIR="$D/bridge" \
  FEED_URL='' TG_TOKEN='123:local-test-only' TG_CHAT='' \
  /path/to/project-python -B -m pytest -q -p no:cacheprovider tests/test_tgdesk.py --basetemp="$D/pytest"
```

Визуальная проверка: `project-python -IB tests/tgdesk_preview.py /absolute/output.png --browser-python /path/to/playwright-python`. Нужны локальные Playwright и `/usr/bin/chromium`. Harness создаёт временную SQLite и вымышленный PDF, запускает реальный FastAPI на loopback со штатным маршрутизатором, но без startup-потоков. Браузер проверяет пустой запуск, затем запускает карточку с подписью тестового бота, скачивает PDF и снимает заполненную форму **без нажатия «Отправить»**. Внешние запросы страницы блокируются. Сервер останавливается, временные данные удаляются; режима демонстрационного доступа в приложении нет.
