# Внешний консультант в чате магазина

`SHOP_CHAT_PROVIDER` выбирает разговорный движок **только для веб-чата покупателя**. Без настройки (`local`) работает прежний `LLM_PROVIDER`. Режим `sitechat` не открывает кабинет EmAGI и не требует входа покупателя: виджет по-прежнему использует `/api/chat`, историю и кнопку менеджера. Внешний консультант — отдельный hosted-агент, не Виктор и не локальный Qwen. Имя базовой модели неизвестно.

## Включение по выбору владельца

Пример для отдельной подготовленной копии приложения с установленными зависимостями, локальными каталогом и справкой и отдельной БД диалогов. См. требования к изоляции путей в [локальном режиме](compact-local.txt). Файл `/run/secrets/shop-sitechat-token` должен быть заранее смонтирован для чтения только процессом сервера; внутри — значение токена, без префикса `Bearer`. Не помещайте значение в команду, `.env`, репозиторий или браузер. Из корня этой копии:

```sh
SHOP_CHAT_PROVIDER=sitechat SITECHAT_TOKEN_FILE=/run/secrets/shop-sitechat-token \
  TG_TOKEN='' WEBIM_TOKEN='' FEED_URL='' PRODUCT_CARDS=0 \
  .venv/bin/python -m uvicorn app.web.server:app --host 127.0.0.1 --port 8000
```

Откройте обычную витрину `http://127.0.0.1:8000/`. Запуск сам по себе не посылает тестовое сообщение. Первый подходящий вопрос покупателя уже вызовет внешний сервис; используйте режим только при разрешённой передаче таких сообщений. `/api/health` показывает выбранного агента, но не читает токен, не проверяет его действительность и не обещает доступность (`online: null`).

**Вернуться к локальному Qwen:** при следующем запуске выберите `SHOP_CHAT_PROVIDER=local COMPACT_LOCAL=1 LLM_PROVIDER=openai LLM_MODEL=qwen3-4b-local LLM_BASE_URL=http://127.0.0.1:18347/v1 LLM_API_KEY=''`. Нужен заранее запущенный локальный сервер из [инструкции Qwen](compact-local.txt). Это выбор оператора, а не автоматическая замена при сбое. Webim и проверочные прогоны используют прежний движок.

## Что происходит с сообщением

1. Приложение проверяет принадлежность диалога, сериализует ходы и обслуживает очередь и принятые человеком обращения в том же чате. Штатные обработчики подбора, справки, расчёта, явной просьбы о КП/счёте и подтверждённых позиций работают локально. Текст внешнего агента не становится аргументом `make_quote`, `make_invoice` или передачи менеджеру.
2. Адрес внешнего POST фиксирован: `https://emagi.ai/sitechat/chat/konsultant-magazina-po`. Сервер посылает `Authorization: Bearer …`, изолированный идентификатор диалога и только текущую очищенную реплику с ролью `user`. Нет истории, client_id, URL страницы, служебных инструкций, реквизитов из БД, карточек, файлов, шагов, операторских заметок и ответов менеджера. Используется штатная маскировка контактов и реквизитов. Для свободного вопроса действует предел 800 символов; ссылки и распознанные вставки с ключами/диагностикой не пересылаются. Такая проверка не распознаёт любую произвольную тайну в свободном тексте: не вставляйте пароли и журналы в чат.
3. После `pending` сервер делает только POST с тем же `channel_context` и `poll:true`, без `messages` (до 12 опросов с паузой 1,5 с, в пределах бюджета хода). `ok` требует непустой текстовый `reply`; он подписывается именем внешнего консультанта. События, файлы и цены не импортируются из ответа. При включённой проверке текст сначала видит менеджер. `not_delivered`, ошибка авторизации/сети, некорректный ответ или исчерпанное ожидание — это **не** успешная доставка. Сообщение не посылается повторно: приложение регистрирует местное обращение и отвечает о передаче. Поздний внешний ответ после этого не забирается.

Контракт не сообщает модель, токены или стоимость. Счётчики и рублёвый бюджет локальной модели не являются учётом или лимитом расхода внешнего агента. Для веб-чата сохраняются слот, ограничение частоты и срок хода. Автоматическое продолжение незавершённого запроса после перезапуска и сквозная дедупликация двух отдельных отправок из браузера не предусмотрены контрактом.

## Проверка без внешнего сервиса

В изолированной копии исходников без `.env`, без рабочей `data/db` (включая симлинк) и без клиентских файлов, с Python проекта:

```sh
env -i PATH=/usr/bin:/bin HOME=/tmp /path/to/project-python -B -m pytest \
  -q -p no:cacheprovider tests/test_sitechat.py tests/test_compact.py tests/test_compact_orders.py
```

Тесты sitechat используют реальный обработчик `/api/chat`, синтетический каталог, временную SQLite, вымышленный токен и `httpx.MockTransport`; сервер не слушает порт, фоновые задачи запуска не включаются. Это проверка контракта и маршрутизации, а не доступности EmAGI, реального секрета или качества ответов живого агента.
