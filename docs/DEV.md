# Разработка

- Python 3.13, окружение `.venv` (fastapi, uvicorn, httpx, snowballstemmer, reportlab, pypdf, pytest).
- Данные заказчика лежат в `data/raw/` (в репозиторий не кладем): `feed.xml` (каталог YML), `buy_part_*_masked.txt` (переписки), `kp_template.pdf`.
- Базы строятся в `data/db/`: `catalog.sqlite` (каталог), `kb.sqlite` (база знаний).
- Модули: `app/catalog` (загрузка и поиск по каталогу), `app/kb` (база знаний), `app/agent` (модель, инструменты, цикл агента), `app/quote` (КП), `app/web` (чат и экран оператора), `eval` (проверочные диалоги).
- Учебный счет: по явному запросу клиента `make_invoice` использует последнее КП диалога. Если реквизитов покупателя достаточно и цены всех строк проверены, PDF выдается автоматически в тот же чат. Другим клиентам файл недоступен; проект не выдается. Ручное выставление сохранено, но кнопка менеджера не обязательна.
- `available=false` не блокирует выдачу: в документе указывается «По фиду: нет в наличии», фактическую поставку подтверждает менеджер. Заказ и срок не обещаются. Если цены нет, менеджер ее рассчитывает; при неоднозначной цене — подтверждает. Автовыдачи в этих двух случаях нет. Отсрочку согласует менеджер отдельно.
- Учебный PDF — не заказ, не для оплаты, без платежных реквизитов. Настоящий счет оформляется в магазине.
- Запуск тестов: `.venv/bin/pytest -q`. Для испытаний задайте отдельные `APP_DB`, `QUOTES_DIR` и `BRIDGE_DIR`.
