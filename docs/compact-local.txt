Компактный локальный режим: настройка и границы

COMPACT_LOCAL=1 LLM_PROVIDER=openai LLM_MODEL=qwen3-4b-local LLM_BASE_URL=http://127.0.0.1:18347/v1 LLM_API_KEY=''
Один слот модели: MAX_PARALLEL_TURNS=1; в проверке TURN_DEADLINE=60. Значение COMPACT_LOCAL по умолчанию 0. Сервер llama.cpp должен принимать response_format=json_schema. Loopback принадлежит конкретному сетевому пространству; отдельный контейнер приложения не увидит чужой 127.0.0.1. Не выставлять порт модели наружу. Не использовать подписочные, сетевые или файловые мосты. Полный цикл с большим промптом при ошибке не включается.

Модель выбирает операцию чтения и ключевые слова. В диалог отправляются выдержки из справки покупателя, а не коммерческие обещания от модели. Пометка оператора «общий ответ» не означает разрешение передать следующему клиенту сырую переписку, контакты, условия отдельного заказа или ответ по другому предмету. Проверять контур на отдельной APP_DB с синтетическими обращениями. Ссылки и цитаты проверяются по локальному слепку; это не проверка доступности сайта магазина.

Путь для покупателя: найти продукт, выбрать один из показанных артикулов и указать количество (можно разными репликами). Формы «Выбираю АРТИКУЛ», «10 шт.», «Подготовьте КП». Количество до выбора артикула уточняет список однозначно найденного продукта. Явный расчёт ранее показанного артикула также сохраняет выбор. Для добавления ещё одной из показанных позиций — «Добавьте АРТИКУЛ, 5 шт.», для замены — «Выбираю …». Новый поиск сбрасывает выбор и количество. Не угадывать артикул по номеру из постороннего диалога. Если у одного артикула несколько показанных вариантов, или количество вне ступени, документ не формируется по догадке. Произвольные списки и свободные договорные условия не поддерживаются.

КП создаёт штатный make_quote; при отсутствии цены она остаётся по запросу, цена при отсутствии товара в фиде не означает наличие или срок поставки. Не вводить оценочные цены. Запрос «Пришлите учебный счёт в этот чат» проверяется штатным make_invoice: только собственный приватный диалог и последнее КП. При нехватке реквизитов — покупатель, напр. в формате ООО «Название», ИНН и КПП; значения остаются в БД приложения. Настоящий заказ не создаётся, счёт не для оплаты. После обновления клиент снова открывает свой диалог; у вложения учебного счёта отдельная проверка владельца. Ссылка КП подписана и является передаваемой ссылкой доступа: не пересылать её, не включать в общие логи. Нельзя выдавать client_id другому браузеру; это часть действующей схемы владения.

При демонстрации: отдельные APP_DB/QUOTES_DIR/CARDS_DB/BRIDGE_DIR, CATALOG_DB и KB_DB только из копий, TG_TOKEN='', FEED_URL='', WEBIM_TOKEN='', PRODUCT_CARDS=0. ADMIN_TOKEN для изолированного оператора создаётся на прогон, не используется ключ рабочего сервиса. Отключить внешние уведомления, не копировать app.sqlite, .env, историю клиентов и рабочие PDF. Для проверки reload получать историю и файл через клиентский API, не считать существование PDF на диске доказательством доставки. Контекстная проверка не заменяет нагрузочный тест или аудит авторизации.
