# ИИ-консультант для чата Softline Store

Хакатон ИИкузница, трек "Клиентские сценарии", задача "Агент поддержки" (заказчик: Софтлайн).

Агент отвечает покупателю в чате сайта store.softline.ru: находит названный продукт в каталоге и доводит до конкретной лицензии уточняющими вопросами, подбирает решение под задачу, если клиент не знает, что ему нужно, отвечает на вопросы об оплате и доставке по базе знаний и готовит черновик КП по шаблону заказчика.

- Стенд: https://ai-support.emagi.co (чат покупателя, витрина каталога, ход работы агента)
- Экран оператора: https://ai-support.emagi.co/admin (диалоги, передачи менеджеру, стоимость)
- Спринт: 26.11.2026 10:00 МСК - 28.11.2026 10:00 МСК

## Что сделано за спринт

| Требование задачи | Как закрыто |
|---|---|
| Клиент называет продукт ("нужен MDaemon Standard"): сверить версии по фиду, задать уточняющие вопросы | `search_products` находит продукт с опечатками и разговорными названиями, `get_product` отдает варианты лицензий, поле `clarify` говорит агенту, что уточнить (пользователи, срок, новая или продление, тип организации), `facets` говорит, какие значения есть в каталоге |
| Клиент не знает, что нужно: выяснить требования и подобрать | до трех вопросов по одному за сообщение (задача, объем, инфраструктура), затем категории и продукты каталога, два варианта с обоснованием |
| Ответы на вопросы по сведениям о продуктах и магазине | карточки вариантов из фида и `kb_search` по справке Softline и служебным страницам магазина, ответ со ссылкой на страницу |
| "А есть ли российский аналог?" | `find_analogs`: ветки "(Импортозамещение)" из самого фида, реестр отечественного ПО из фида, справочник российских вендоров |
| Черновик КП по шаблону после согласия клиента (необязательное) | `make_quote`: PDF по шаблону заказчика, суммы и НДС считает код, пометка "черновик, проверяет менеджер" |
| Экономить время менеджеров | темы, которые агент не решает (скидки, тендеры, статус заказа, жалобы), уходят менеджеру готовой сводкой; экран оператора показывает очередь |

Не сделано и не входит в поставку:
- встраивание в действующий чат сайта (у магазина Webim) и связь с 1С или CRM: по условиям задачи интеграции не требуются, на стенде свой чат;
- остатки и сроки поставки в реальном времени: в фиде есть только признак "в продаже" и цена;
- счет: агент его не выставляет, передает менеджеру вместе с черновиком КП;
- вход оператора по паролю и ответ оператора клиенту из экрана оператора: экран только для чтения.

## Как это работает

```
 Чат на странице --> /api/chat --> Цикл агента (до 8 шагов на реплику)
 (страница товара)                   |  модель выбирает инструмент, код исполняет,
                                     |  модель получает результат и решает дальше
                                     v
   search_products  get_product  browse_categories  find_analogs     <- каталог, SQLite + FTS5
   kb_search                                                         <- база знаний, SQLite + FTS5
   note_facts                                                        <- память о клиенте
   calc_total  make_quote                                            <- арифметика и PDF кодом
   handoff_to_manager                                                <- очередь оператора
                                     |
                                     v
   Проверки кодом: цены только из каталога, лимит шагов, ответ при сбое
                                     |
                                     v
   Ответ клиенту + карточки товаров + кнопки выбора + след шагов с токенами и рублями
```

### Цикл агента

Один ход клиента это до 8 вызовов модели. На каждом шаге модель либо вызывает инструмент, либо отвечает клиенту. Модель не знает цен и наличия: в инструкции прямо сказано брать их только из ответов инструментов, а код это проверяет.

Проверки, которые не зависят от модели (`app/agent/loop.py`):
- **Цены.** Любая сумма в рублях в ответе должна встречаться в данных инструментов этого диалога или в словах самого клиента. Нашлась чужая сумма: ответ возвращается модели на переписывание с указанием, какие суммы лишние. Не исправила: суммы заменяются на "цена по запросу".
- **Арифметика.** Цена на количество и итог по позициям считает `calc_total`, сумму и НДС в КП считает `make_quote`. Модель не умножает.
- **Лимит шагов и сбои.** Модель недоступна, зациклилась на инструментах или вернула пустой ответ: клиент получает честное сообщение, обращение уходит менеджеру.
- **Чужие инструкции.** Текст клиента для модели это данные. Неизвестный инструмент или неверные аргументы возвращаются модели ошибкой, диалог не падает.

### Инструменты

| Инструмент | Что делает |
|---|---|
| `search_products` | поиск продуктов по названию, вендору, артикулу или задаче; опечатки, транслит, смешанная раскладка букв; фильтры: только в продаже, только российское, категория |
| `get_product` | варианты лицензий продукта с ценой и артикулом; фильтры по пользователям, узлам, количеству, сроку, типу лицензии и организации, версии, платформе; подсказка, что уточнить |
| `browse_categories` | категории каталога по описанию задачи |
| `find_analogs` | аналоги из той же категории, по умолчанию российские |
| `kb_search` | справка: доставка лицензий, оплата, НДС, документы, возврат, личный кабинет, акции |
| `note_facts` | запомнить, что клиент сообщил о себе и задаче |
| `calc_total` | сумма по позициям |
| `make_quote` | черновик КП в PDF |
| `handoff_to_manager` | передать менеджеру со сводкой: кто клиент, что нужно, что подобрано |

### Память и контекст

- Диалог: модель видит последние реплики, сохраненные факты о клиенте и список уже найденных продуктов и вариантов с id и ценами.
- Между визитами: тот же покупатель возвращается (идентификатор в браузере), агент видит, что обсуждали раньше, и не переспрашивает.
- Страница сайта: чат передает адрес страницы, с которой пишет клиент. 31 из 72 обращений без названия продукта написаны с карточки товара ("ваша цена?"), без адреса страницы на них не ответить.

## Данные заказчика и что из них извлечено

**Каталог** (`app/catalog`). Фид YML: 136 040 предложений, 9 311 категорий, 1 232 вендора. В продаже с ценой 44 601, с ценой 55 771, у остальных цена 0: агент называет это "цена по запросу". Предложения собраны в 12 538 продуктов (4 413 линеек софта и 8 125 отдельных товаров), у каждого варианта разобраны срок, пользователи и узлы, тип лицензии, тип организации, версия, платформа. Сборка базы из фида занимает около минуты, поиск отвечает за миллисекунды.

Что оказалось важным в данных:
- **Ступени количества.** У 23 167 предложений цена зависит от объема закупки ("от 100 до 149 шт."), в названии ступень не видна. Фильтр по количеству выбирает нужную ступень.
- **Один артикул с несколькими ценами.** Таких артикулов 808. У 319 различие извлекается (ступень, срок, тип организации), у 489 нет: вариант получает флаг `price_ambiguous`, агент показывает вилку и уточняет либо передает менеджеру.
- **Российское ПО.** Номер реестра отечественного ПО в фиде есть только у 1 208 предложений (20 продуктов). Поэтому признак "российский" собирается из трех источников: номер реестра из фида, ветки категорий "(Импортозамещение)" из фида, справочник `data/ru_vendors.txt` на 256 вендоров. Справочник составлен вручную по списку производителей фида, это допущение.
- **Примера из задачи в фиде нет.** Редакции "MDaemon Standard" в каталоге нет, есть MDaemon на 2 и 3 года, MDaemon Messaging Server на 1 год и дополнения. Агент говорит это прямо и предлагает то, что есть.

**База знаний** (`app/kb`). 366 страниц, 2 171 кусок: справка docs.softline.com (личный кабинет, учетная запись, оплата) и 22 служебные страницы магазина (оплата и доставка, правила продажи, контакты, тендеры, акции). Справка по другим сервисам Softline (для продавцов и разработчиков) в выдаче понижена: покупателю магазина она не нужна.

**Переписки** (`docs/chat_analysis.md`). Прочитаны все 495 обращений. 85% называют продукт, 42% спрашивают цену, из них 72% без количества. КП или счет просят 26%, каждое пятое обращение содержит несколько вопросов, 9,5% это "не знаю, что нужно". Из разбора взяты правила инструкции (цена или вилка сразу и один вопрос, не просить ИНН ради цены, не обобщать "не продаем" на весь вендор), список тем, которые сразу идут менеджеру, словарь разговорных названий ("кес", "ксп", "астра орел") и проверочный набор.

**Шаблон КП** (`app/quote`). Черновик повторяет шаблон заказчика: шапка, таблица "Артикул, Наименование, Кол-во, Цена, Сумма, В т.ч. НДС", условия оплаты и поставки, срок действия. НДС 22/122; позиции с номером реестра отечественного ПО идут "Без НДС"; позиции с ценой по запросу и позиции не в продаже помечаются для менеджера. Пример: `docs/kp_example.pdf`.

## Проверка качества

- `pytest`: 112 тестов. Каталог и база знаний на данных заказчика, КП (суммы и НДС считаются в тесте независимо), цикл агента на модели-сценарии: проверка цен, лимит шагов, сбой модели, память между визитами.
- `eval/cases.jsonl`: 60 проверочных диалогов, 57 начинаются с реального обращения из переписок, один повторяет пример заказчика дословно. У каждого ожидания: какие инструменты вызвать, о чем спросить, что упомянуть, чего не делать, нужна ли передача менеджеру или КП.
- `python -m eval.run` проигрывает набор через агента и пишет отчет: доля диалогов без ошибок, доля закрытых без менеджера, вызовы и токены на реплику, стоимость запроса и диалога.

## Стек и модели

- Python 3.13, FastAPI, SQLite с FTS5 (каталог, база знаний, диалоги), reportlab (PDF), httpx, snowballstemmer. Интерфейс без фреймворков: HTML, CSS, JS.
- Модель подключается через один интерфейс (`app/agent/llm.py`), меняется настройкой:
  - GigaChat API (функции, российская модель, данные в РФ);
  - любой OpenAI-совместимый сервис, в том числе модель с открытыми весами в своем контуре через vLLM или Ollama.
- Векторного поиска нет намеренно: названия продуктов, артикулы и опечатки лучше ловятся полнотекстовым поиском с триграммами и транслитом, а смысловой подбор ("защитить почту") делает модель через категории каталога.

## Запуск

```bash
git clone https://github.com/simonsafronov/ai-support-agent && cd ai-support-agent
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # вписать ключ модели

mkdir -p data/raw               # положить сюда feed.xml из материалов задачи
.venv/bin/python -m app.catalog.ingest      # каталог -> data/db/catalog.sqlite, около минуты
.venv/bin/python -m app.kb.crawl fetch      # скачать справку и страницы магазина
.venv/bin/python -m app.kb.crawl build      # база знаний -> data/db/kb.sqlite

.venv/bin/uvicorn app.web.server:app --port 8000
.venv/bin/pytest -q             # тесты
.venv/bin/python -m eval.run    # проверочные диалоги, отчет в eval/runs/
```

Либо `docker compose up --build` после сборки баз (том `./data`).

Состав поставки: `app/` (каталог, база знаний, агент, КП, веб), `eval/` (набор и прогон), `tests/`, `docs/` (разбор переписок, пример КП), `data/ru_vendors.txt`, `certs/` (корневые сертификаты для GigaChat API). Данные заказчика (фид, переписки, шаблон) в репозиторий не входят.

## Вопросы к заказчику, от которых зависят цифры

1. Цена 0 в фиде (80 269 предложений): это "по запросу" с передачей менеджеру, или цену можно брать из другого источника?
2. Требования к модели: только российская, только в своем контуре, или допустим внешний API?
3. Есть ли полный справочник реестра отечественного ПО по позициям каталога? В фиде он заполнен у 0,9% предложений.
